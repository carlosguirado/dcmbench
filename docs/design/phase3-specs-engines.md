# Phase 3: spec v2 and engines

Status: **implemented 2026-10-20** (`dcmbench/specs/`, `dcmbench/engines/`). The 0.1.x adapters, benchmarker, utilities, spec builder and dataset loader were deleted. Section numbers like "Plan §3.4" refer to `docs/PLAN.md`.

## The division of labour

**Engines only estimate.** `BiogemeEstimator` and `TorchEstimator` take a spec and a `ChoiceProblem` and return a `SpecModel`. DCMBench computes everything else from the spec and the estimated parameters, identically for both engines:
- predictions;
- log-likelihoods;
- per-draw probabilities;
- exact marginal utilities, by symbolic differentiation of the formulas.

```python
from dcmbench.specs import load_spec
from dcmbench.engines.biogeme import BiogemeEstimator   # or dcmbench.engines.torch.TorchEstimator

spec = load_spec("swissmetro_mnl.json")
fitter = BiogemeEstimator(spec, dataset.problem)   # a ModelFitter: use with evaluate() or InternalValidator
model = fitter(dataset.frame)                      # SpecModel
model.coefficients(), model.loglikelihood(dataset.frame), model.predict_probabilities(dataset.frame)
```

## Spec v2 (`dcmbench/specs/spec.py`)

**Fields:**
- `spec_version: 2`, `name`, `description`;
- `model`: `MNL`, `NL` or `MXL`;
- `alternatives`: named as in the dataset's `ChoiceProblem`;
- `parameters`: `start`, `lower`, `upper`, `fixed`;
- `utilities`: one formula per alternative;
- `nests` (NL only);
- `random_parameters` and `draws` (MXL only).

Choice codes and availability come from the `ChoiceProblem`, not the spec. Unknown fields, unused parameters, undefined references and inconsistent bounds are errors.

**Expression language** (`expression.py`). Formulas are parsed with Python's `ast` into an allow-listed tree:
- numbers and names;
- `+ - * / **` and unary minus;
- `log()` and `exp()`;
- single comparisons (`== != < <= > >=`), which act as 0/1 indicators.

Anything else is rejected; there is no `eval()`. Names that are not parameters or random parameters are data columns. Data stay in original units, so any scaling is part of the formula (e.g. `B_COST * TRAIN_CO * (GA == 0) / 100`).

**Random parameters.** Each is built from a standard draw ξ:

| Distribution | Coefficient |
|---|---|
| `normal` | mean + spread·ξ |
| `lognormal` | sign·exp(mean + spread·ξ), with `sign` ±1 |
| `uniform` | mean + spread·(2u − 1) |
| `triangular` | mean + spread·t, t symmetric on [−1, 1] |

**Draws.** `number`, `seed`, `type` (`pseudo` or scrambled `halton`) and `panel`. With `panel: true`, one draw is shared across all of a respondent's observations, using `ChoiceProblem.group_column`.

**v1 specs** (`v1.py`). These convert to v2 plus an implied `ChoiceProblem`, with alternatives named by their v1 keys. `validation.BiogemeSpecFitter` and `fitter_from_spec` keep their interface and now run on this path. v1 still cannot express random parameters (`NotImplementedError`).

## Conventions (`compute.py`)

- **Availability.** Unavailable alternatives get utility −1e100 rather than −∞, which keeps torch gradients finite.
- **Nested logit.** This uses Biogeme's parameterization. μ_m ≥ 1 scales utilities inside nest m, and the logsum coefficient is 1/μ_m; alternatives in no nest form singleton nests. A model consistent with random utility needs μ_m ≥ 1.
- **Mixed logit.** Probabilities are averages of logit probabilities over draws. With panel draws, a respondent's likelihood is the average over draws of the product over their choices.
- **Draws are generated by DCMBench.** They depend only on (number of units, number of draws, seed, type, parameter index) and are passed to Biogeme as user-defined random number generators. Consequences:
  - Biogeme and PyTorch estimate on identical draws.
  - Predictions are deterministic (common random numbers across perturbations).
  - The engine-consistency check below is exact.
- **Panel units.** Respondents are ordered by their sorted ID; estimation data are sorted by ID first, as Biogeme requires.

## Engines

**`BiogemeEstimator`** (`engines/biogeme.py`, Biogeme ≥ 3.3):
- It compiles the spec to Biogeme expressions and estimates the model.
- It writes no files: in-memory parameters, and no HTML, YAML or iteration output.
- It reports robust standard errors.
- **Consistency guard.** The log-likelihood DCMBench computes at Biogeme's estimates must match the one Biogeme reports (relative tolerance 1e-6). Otherwise it raises `EngineMismatchError`.

**`TorchEstimator`** (`engines/torch.py`):
- The spec is compiled to torch through the same likelihood code.
- Gradients come from autograd; scipy's L-BFGS-B handles exact bounds.
- Robust standard errors are the sandwich H⁻¹BH⁻¹.
  - H is the autograd Hessian.
  - B is the outer product of per-unit scores, computed in forward mode: one pass per parameter. Reverse mode would need one pass per observation.

**`SklearnFitter`** (`engines/sklearn.py`):
- It works with any classifier with `predict_proba`, cloned per fit.
- Features are listed explicitly.
- The model declares `handles_availability = False`, so DCMBench masks and renormalizes its probabilities.
- `n_params` is `None`, so ρ̄² is not applicable.
- Tree, ensemble and nearest-neighbour estimators are marked `piecewise_constant`.

**`PrecomputedModel`** (`engines/precomputed.py`):
- It scores probabilities computed elsewhere (e.g. Apollo), looked up by a key column.
- It is `static`, so `evaluate()` refuses behavioral analyses for it: the probabilities cannot respond to changed data.

## Verification

- **Parity on the ten 0.1.x benchmark specs** (written as spec v2 in `tests/fixtures/v0_1_baseline/specs/`, transcribed exactly). Biogeme and PyTorch agree to:
  - LL within 3·10⁻⁶;
  - coefficients within 2·10⁻⁴;
  - robust standard errors within 0.02%.

  This holds wherever both reach the same optimum. Synthetic MNL, NL and panel-MXL parity tests run in CI.
- **Known truth.** PyTorch recovers the true parameters of a synthetic MNL and a panel mixed logit, including the spread, within 3.5 standard errors.
- **Regression against 0.1.x** (`tests/test_v0_1_regression.py`, network). Through the full new stack, the closed-form benchmark models reproduce the 0.1.x results:
  - full-sample LL;
  - 80/20 holdout in-sample and out-of-sample LL, macro F1 and macro recall;
  - the Swissmetro car-cost scenario.

  Holdout splits stratify on the alternative's position in the choice problem, which reproduces the 0.1.x split.

## Known issues

- **Local optima in mixed logit.** On the LPMC lognormal MXL, Biogeme stopped at LL −4529.27 while PyTorch found −4527.01, from the same starting values. Zero spread is a stationary point by symmetry. MXL benchmarks should compare more than one starting point, or more than one engine, before reporting.
- **ModeCanada NL as specified in 0.1.x** (nest parameter bounded to [0.001, 1]) does not converge reliably. It is excluded from the regression test.
